## 1. Задача

Сверстать и анимировать интерактивную страницу с итогами года для клиента сервиса аналитики
по макетам. Страница состоит из секций: заставка, «Главные итоги»,
«Фактическая выгода», «Выручка и депозиты», «Топ контрагентов», «Топ получателей»,
«Расходы и денежный поток», «Налоги и баллы», «Обращения», «Бизнес-карты» и финальный экран. У
каждой секции есть варианты по наличию данных, они показаны на макетах.

Разработка ведётся **в отдельном репозитории** на моковых данных. Готовый код затем встраивается
в наш проект командой заказчика. Поэтому главный критерий — **лёгкость переноса**: модуль не знает,
откуда берутся данные и куда уходят события.

## 4. Требования к встраиванию

### 4.1. Публичный контракт

Модуль экспортирует один компонент:

```tsx
type TYearlyReportProps = {
  screen: TYearlyReportScreen;
  loadData: () => Promise<TYearlyReportData>;
  onClose: () => void;
  onAction: (action: TYearlyReportAction) => void;
  onScreenChange: (screen: TYearlyReportScreen) => void;
};
```

- `loadData` — функция получения всех данных. Компонент вызывает её при монтировании и сам
  показывает экран загрузки, а при отклонённом промисе — экран ошибки с кнопкой «Повторить»
  (повторный вызов `loadData`). Результат не применяется, если компонент уже размонтирован.
- `screen` — якорь: id секции, к которой прокручена страница. Страница — одна прокручиваемая
  лента секций (макет), поэтому «экран» здесь — секция. `TYearlyReportScreen` — union id секций,
  описывается в `types.ts`: `'intro'` (заставка), `'summary'` («Главные итоги»), `'benefit'`
  («Фактическая выгода»), `'revenue'` («Выручка и депозиты»), `'top-clients'`, `'top-contractors'`,
  `'cash-flow'` («Расходы и денежный поток»), `'taxes'` («Налоги и баллы»), `'support'`
  («Обращения»), `'business-cards'`, `'finale'`. Id попадают в адрес страницы (якоря), поэтому их
  не переименовывать. Когда значение пропа меняется, модуль прокручивает страницу к началу
  секции (плавно; мгновенно при первом показе и при `prefers-reduced-motion`). Если секции нет на
  странице (например, нет контрагентов), прокрутки нет.
- `onScreenChange` — сообщает, что при прокрутке (колесо, тач, клавиатура, кнопки «Смотреть итоги» и
  «Продолжить с текущими данными») верхней видимой секцией стала другая; вызывается один раз на
  смену секции, а не на каждый кадр прокрутки. Прокрутка, вызванная изменением `screen`, не
  порождает вызов `onScreenChange`. Адрес страницы синхронизируем мы.
- `onAction` — пользователь нажал кнопку или ссылку, которая ведёт за пределы модуля («Подключить
  другие банки», «Забрать подарок» и т. п.). Список действий — в `yearly-report-contract.md`;
  переход выполняем мы.
- `onClose` — пользователь нажал «выйти/закрыть».
- Экраны загрузки и ошибки — по макету. Кнопка «Повторить» на экране ошибки вызывает `loadData`
  снова.

### 4.2. Запреты внутри модуля

- Никаких `fetch`/`axios`/`XMLHttpRequest`, `localStorage`/`sessionStorage`, cookie. Данные
  модуль получает только через `loadData`; адреса запросов и авторизация ему неизвестны.
- Никакого обращения к `window.location`, `history`, роутеру. Текущая секция приходит пропом
  `screen`, смена секции сообщается через `onScreenChange`. В песочнице храните `screen` в
  `useState` или в хэше адреса (`#income`) — к нам это не переносится.
- Никаких глобальных стилей и reset, стилей на `html` и `body`, слушателей без снятия в cleanup:
  модуль не должен влиять на остальную страницу. Стили, которые emotion добавляет в `<head>`
  сам, допустимы.
- Никаких `new Date()` в логике: «текущий» год приходит в данных из `loadData` (поле `year`).
- Без `console.*` и закомментированного кода.

### 4.3. Размещение на странице

Страница встраивается под шапкой платформы, но у вас её нет, поэтому высота шапки модулю неизвестна
и не должна учитываться в вёрстке: модуль занимает всё доступное место родителя.

- Корень модуля занимает **100 % высоты и ширины родителя** (`height: 100%`); `100vh`/`100dvh`
  напрямую не использовать.
- В песочнице эмулируйте шапку фиксированным блоком 64 px и проверяйте, что модуль корректно
  работает при её высоте от 0 до 100 px.
- Все z-index — в локальном stacking context корня (`isolation: isolate`).
- Шрифт — внутри модуля `font-family: inherit`, шрифты в модуль не подключать. В песочнице шрифт
  подключается снаружи модуля (на странице-песочнице) — обязательно, чтобы проверить корректность
  вёрстки на реальных начертаниях. Файлы шрифта запросите у дизайнера.
- Цвета и размеры — константами в одном файле `common/theme.ts`, чтобы мы могли подогнать их под
  токены платформы.

## 5. Данные и моки

Контракт данных зафиксирован в отдельном файле `yearly-report-contract.md`: типы, назначение
каждого поля, допустимые значения и пустые состояния (контрагентов от 0 до 3, любой карточки может
не быть и т. д.). Типы в `types.ts` повторяют его один в один; всё, чего в контракте нет, модуль не
получает и не показывает. Изменение контракта — только по согласованию с заказчиком.

Моки типизируются контрактом и лежат в `mocks/`. Верстка обязана корректно работать в любой
комбинации карточек: любая из них может быть в пустом состоянии.

### Сценарии моков (обязательны, переключаются в песочнице)

1. Все данные есть; клиент платил бизнес-картой.
2. Минимум данных: все карточки в пустом состоянии (`null`, пустые списки).
3. По каждой секции — каждая карточка отдельно в пустом состоянии, остальные заполнены (пустые
   состояния и тексты — по макетам).
4. Топ клиентов и топ получателей: по 0 / 1 / 2 / 3 элемента, в том числе разное число в двух
   топах (заголовки «Топ-3» / «Топ-2» / «Главный …»). Для 0 — `TODO(Q8)`.
5. Нет данных за предыдущий год: показывается только текущий.
6. Клиент не платил бизнес-картой (`kind: 'withoutPayments'`); участие в акциях и кэшбэк в
   пустом состоянии у `kind: 'withPayments'`.
7. Фонд «Налоги» открыт и не открыт; план по выручке задан и не задан.
8. Отрицательный денежный поток (`cashFlow.net`) — вид по макету `TODO(Q5)`.
9. Экстремальные значения: названия по 300 символов, в том числе слова без пробелов; в каждой
   карточке максимально широкое значение (три цифры с «тыс ₽» / «млн ₽», число контрагентов
   от 100 до 9 999); суммы от 0,01 до 999 999 999 999,99.
10. Загрузка: `loadData` отвечает с задержкой (в песочнице — настраиваемой).
11. Ошибка: `loadData` отклоняет промис; «Повторить» вызывает его снова и при успехе
    показывает данные.

Каждый сценарий проверяется на всех брейкпоинтах (см. «Брейкпоинты» в п. 6).

## 6. Дизайн и адаптив

- Макеты. Верстка — пиксель-в-пиксель на контрольных ширинах.
- Мобильные: iOS Safari и Chrome Android; учесть динамическую панель адреса (не опираться на
  `100vh`), блокировать горизонтальный overscroll (`overscroll-behavior-x: none`) внутри модуля.
- Десктоп: актуальные Chrome, Safari, Firefox, Edge (последние 2 версии).
- Анимации: 60 fps на среднем Android; анимировать `transform`/`opacity`, не `top/left/height`.
  Уважать `prefers-reduced-motion` (анимации заменяются мгновенным переключением).
- Анимации не блокируют прокрутку и ввод; повторные клики не ломают состояние.
- Все картинки и иллюстрации — PNG в масштабе 2x (размер в CSS вдвое меньше размера файла в
  пикселях). SVG не используем: на нём были проблемы в Safari. Каждый файл оптимизирован
  (сжатие PNG без заметной потери качества). Файл подключается обычным импортом
  (`import image from './image.png'`) и выводится тегом `<img>` без `srcset`: один файл 2x.
  Картинки ниже первого экрана — `loading="lazy"` и `decoding="async"`, на первом экране —
  `loading="eager"`. Картинка занимает ширину контейнера и вписывается в него (`object-fit:
  contain`), искажение пропорций недопустимо.

### Брейкпоинты

Брейкпоинты: **375, 1024, 1440**.

Каждый сценарий из п. 5 на каждом из них, на ширинах между ними и ниже 375 должен выглядеть
корректно: без обрезанного и налезающего текста, без горизонтальной прокрутки страницы.

## 7. Тексты и типографика

- Все тексты русские, в одном месте по экрану (константы, не вперемешку с JSX).
- **Все тексты должны быть оттипографлены** — заголовки, описания, подписи кнопок, сообщения
  об ошибке, `aria-label` и `title`. Проверяйте типографом (например, сервис Типограф)
  до сдачи; статические тексты записывайте в константы уже оттипографленными.
- Что именно: неразрывные пробелы после предлогов и перед «₽»/«%», «ёлочки» в кавычках,
  длинное тире, числительные склоняются корректно («1 клиент», «2 клиента», «5 клиентов»).
- Названия организаций выводятся как пришли; длинные — с переносом/обрезкой с `title`.

## 8. Доступность

- Все управляющие элементы — реальные `<button>`/`<a>`, доступны с клавиатуры, видимый focus.
- Смена секции озвучивается (`aria-live` или фокус на заголовке новой секции).
- У декоративных изображений `aria-hidden`, у смысловых — `alt`.

## 9. Качество кода

- TS strict, нет `any` и `as` для подавления ошибок типов; исчерпывающая проверка `switch`
  по union/enum (`default` с проверкой на `never`).
- Компоненты — функциональные, один компонент на файл, файл называется по компоненту в kebab-case.
- Утилиты (форматирование сумм/процентов/дат/склонений) — отдельными файлами рядом с компонентом.
  Тесты на них по желанию, не обязательны.
- Хуки и компоненты не мемоизируются «на всякий случай» — только при реальной причине.
- Проверка типов и линтер проходят без ошибок и предупреждений (если тесты есть — они тоже).
